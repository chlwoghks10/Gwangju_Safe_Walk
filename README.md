# 광주 안심길

공공데이터 기반 광주 안전 보행 경로 비교 안내 앱

**팀 익셉션** · 조선대학교 정보통신공학과 캡스톤디자인

---

## 무엇을 만드나

밤에 혼자 걸을 때 어느 길이 나은지 알 방법이 없습니다.
지도 앱은 최단 경로만 알려주고, 안심시설을 반영한 경로 안내는 다른 지자체에만 있습니다.

이 앱은 **최단 경로와 안전 우선 경로를 나란히 제시하고, 각 경로에 어떤 시설이 있는지 지도와 수치로 보여줍니다.**

### 설계 원칙

> **안전을 판정하지 않습니다. 판단할 근거를 제시합니다.**

어느 길이 안전한지는 증명할 수 없습니다. 사고가 일어나지 않았다는 것은 측정되지 않기 때문입니다.
대신 **"이 경로에 CCTV와 보안등이 몇 곳 있다"는 사실은 현장에서 확인할 수 있습니다.**
시스템은 경로를 대신 고르지 않고, 두 경로의 정보를 제시하고 선택은 사용자가 합니다.

광주에는 여성안심귀갓길 55개 구간이 지정돼 있으나 고정 구간이며,
출발지와 도착지에 맞춰 경로를 안내하는 서비스는 확인되지 않았습니다.

### 1. 공공데이터 수집 및 정제

| 데이터 | 원본 | 정제 후 |
|---|---|---|
| CCTV | 6,805행 | **6,802지점** |
| 보안등 | 33,548행 | **18,745지점 / 22,893개** |
| 안전비상벨 | — | **158지점** |
| 경찰서·지구대 | — | **40지점** |

- 동일 좌표에 연도별 중복 등록된 증설 기록을 지점 단위로 통합, 대수 합산
- 좌표 결측 및 행정구역 범위 이탈 값 제거
- 지도 레이어는 GeoJSON 으로 형식 통일

### 2. 보행 도로망 구축 및 구간별 시설 집계

- OSMnx로 조선대 반경 1km 보행 전용 도로망 확보 — **노드 1,616 / 간선 4,211 / 총 연장 102km**
- 구간 꺾은선을 따라 점–선분 최단거리로 반경 내 시설 집계
- 매칭 반경 30m → 50m 상향 후 CCTV 미보유 구간 79% → **69%**, 보안등 57% → **48%**

### 3. 경로 탐색 및 비교

시설 밀도가 낮을수록 통행 비용이 증가하도록 비용 함수를 설계하고 두 경로를 동시에 산출합니다.

| 경로 | 거리 | 보안등 |
|---|---|---|
| 최단 | 1,606 m | 27곳 |
| 안전 우선 | 2,359 m | 88곳 |

### 4. 가중치 민감도 분석

계수를 0.5~5.0 범위에서 변경하며 경로 변화를 측정했습니다.

| 계수 | 거리 | CCTV | 보안등 | 기준 경로 일치율 |
|---|---|---|---|---|
| 0.5 ~ 2.0 | 1,606 m | 16 | 38 | 100% |
| 3.0 | 2,504 m | 60 | 128 | 18% |
| 5.0 | 2,544 m | 64 | 130 | 21% |

**계수 2와 3 사이에 분기점이 존재**하며, 점진적 변화가 아닌 경로 전환이 발생합니다.
대상 지역의 도로 구조에서 비롯된 것으로 해석합니다.

### 5. 경로 API 서버 (AWS EC2)

경로 계산과 이상 판정은 서버에서 수행하고, 앱은 좌표를 보내고 결과를 받아 그립니다.
프로토타입은 FastAPI로 만들었고(`server/`), 외부 패키지 없이 올리기 위해 Java 표준 라이브러리로 다시 작성했습니다.

```
  안드로이드 앱                       AWS EC2 서버
 ┌──────────────┐  출발·도착 좌표  ┌─────────────────────────┐
 │ 지도에서 출발·│ ───────────────> │ /route                  │
 │ 도착지 선택   │                 │  ├ 최단 / 안심 A / 안심 B │
 │              │  경로 3개 +      │  └ 경로 주변 시설 조회    │
 │ 경로 선택    │ <─────────────── │    (반경 50m, 격자 색인)  │
 ├──────────────┤                 ├─────────────────────────┤
 │ 안내 중      │  이탈 시 좌표    │ /track                  │
 │ (2초마다 측위)│ ───────────────> │  └ 벗어난 경로만 재탐색   │
 │              │                 ├─────────────────────────┤
 │              │  5초마다 좌표    │ /watch                  │
 │              │ ───────────────> │  └ 정지·신호 두절 판정    │
 └──────────────┘ <─────────────── └─────────────────────────┘
                   확인 요청 / 이상 알림
```

### 6. 안드로이드 앱

- 스플래시 → 대시보드 → 안심지도 / 안심경로 / 메뉴 화면 구성
- 네이버 지도 SDK 연동
- **정제 데이터 25,745지점을 지도에 표시** (화면 범위 기준 렌더링, 줌 단계별 레이어 표시)
- CCTV·보안등·비상벨·경찰서 레이어 개별 토글
- 지도 탭으로 출발·도착 지정 → 서버 호출 → **세 경로와 경로에 쓰인 시설을 함께 표시**
- EC2 재시작 시 주소가 바뀌므로 앱 내에서 서버 주소 변경 가능(차후 탄력적 IP 사용)

### 7. 턴 안내 내비게이션

- 서버가 경로 좌표열에서 회전 지점을 추출해 안내 문구를 생성
- 앱은 2초마다 측위하고, 다음 회전까지 30m 안에 들어오면 음성 안내, 12m를 지나면 다음 회전으로 넘김
- 정확도 30m를 넘는 측정은 사용하지 않음
- 같은 모퉁이에서 안내가 반복되는 문제를 회전 지점 병합으로 해결 — 실측 **161회 → 115회**

### 8. 경로 이탈 재탐색

- 앱이 경로와의 수직거리를 계산해 **30m 초과가 2회 연속**이면 이탈로 판정
- 이탈 시 현재 좌표를 `/track`으로 보내 **따라가던 경로 하나만** 다시 받음
- 세 경로를 모두 다시 요청할 때와 비교해 응답 **9.9KB → 2.9KB**, 소요 **0.055초 → 0.026초**
- 새 경로에 올라서기 전까지는 다시 이탈로 보지 않음

### 9. 이상 탐지 및 긴급 연락

안내 중 5초마다 좌표를 보내고, 서버가 상태를 판정합니다.

| 조건 | 판정 |
|---|---|
| 반경 25m 안에서 3분 이상 정지 | 확인 창 표시 |
| 확인 창 무응답 또는 6분 경과 | 보호자에게 알림 |
| 3분 이상 좌표 수신 없음 | 신호 두절로 기록 |

- 확인 창 15초 무응답 시 보호자에게 현재 위치를 문자로 발송하고, 벨소리를 최대로 올리며 112 연결 버튼을 표시
- 보호자 번호는 **단말에만 저장하고 서버로 보내지 않음**
- 문자는 단말에서 발송하므로 전원이 꺼진 경우는 서버 기록으로만 남음

### 10. 백그라운드 안내

- 안내 중에만 알림을 띄우는 포그라운드 서비스를 두어 화면을 꺼도 위치 수신이 이어짐
- 앱을 종료하면 서비스도 함께 종료되어 서버가 신호 두절로 인식

## 실행 방법

### APK 설치

[Releases](../../releases)에서 `app-debug.apk`를 내려받아 설치합니다.
설치 시 "출처를 알 수 없는 앱" 경고가 표시되면 허용해 주세요.

**경로 비교는 서버가 실행 중이어야 동작합니다.**

### 서버 실행

```
javac -cp lib/gson-2.11.0.jar -d out src/*.java
java -cp out:lib/gson-2.11.0.jar Server
```

확인: `http://<주소>:8000/health`

장소 검색과 보행자 경로에는 외부 API 키가 필요합니다.
키는 저장소에 두지 않고 서버의 환경변수 파일(`safewalk.env`)에서 읽습니다.

프로토타입 FastAPI 서버는 `server/` 에 있습니다.

```
pip install -r requirements.txt
uvicorn main:app --host 0.0.0.0 --port 8000
```

### 소스 빌드

```
Android Studio에서 프로젝트를 열고 Gradle Sync 후 실행
```

지도 표시에는 네이버 클라우드 플랫폼 Application 키가 필요합니다.
`AndroidManifest.xml`의 `NCP_KEY_ID` 값을 본인 키로 교체하고,
콘솔에 Android 패키지명 `com.exception.gwangju_safe_walk`를 등록해야 합니다.

## 확인된 한계

데이터를 직접 검증하며 확인한 제약을 기록합니다.

- 공공데이터는 **설치 기록**이므로 실제 점등 여부나 고장 상태는 알 수 없습니다.
- 매칭 반경 50m는 도로 폭과 건물 가림을 반영하지 못해, 길 건너편 시설도 함께 집계됩니다.
- 가중치 계수 2와 3 사이에서 경로가 한 번에 전환되어, 중간 수준의 대안 경로를 만들기 어렵습니다.
- 정확도 30m를 넘는 측정을 버리므로 건물 사이나 실내 진입 구간에서 안내가 끊깁니다.
- 긴급 문자를 단말에서 보내므로, 전원이 꺼진 경우 보호자에게 전달되지 않고 서버 기록으로만 남습니다.
- 탄력적 IP를 쓰지 않아 EC2를 재시작하면 주소가 바뀌고, 통신은 아직 평문 HTTP입니다.
